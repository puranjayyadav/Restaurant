# Supabase Integration Guide

## Overview

This integration solves the **duplicate venue problem**: when a place like "Ace Hotel Lobby" appears in multiple vibe searches (work_friendly, aesthetic, coffee_run), it's stored once in the database with multiple vibe associations.

## Architecture

### Two-Table Design

1. **`venues`** table: Stores unique places (deduplicated by `place_id`)
2. **`venue_vibes`** table: Links venues to vibes (many-to-many relationship)

This allows you to:
- Store each venue once, even if it matches 10 different vibes
- Query by vibe: "Show me all speakeasies"
- Query by neighborhood: "Show me all SoHo places"
- Query by combination: "Show me work-friendly cafes in SoHo"

## Setup

### 1. Install Dependencies

```bash
pip install supabase python-decouple
```

### 2. Configure Credentials

Create a `.env` file in the `google_maps_scraper` directory:

```
SUPABASE_URL=https://your-project.supabase.co
SUPABASE_KEY=your-anon-key
```

Or set environment variables:

```bash
export SUPABASE_URL="https://your-project.supabase.co"
export SUPABASE_KEY="your-anon-key"
```

### 3. Create Database Tables

Run this SQL in your Supabase SQL Editor:

```sql
-- 1. Create the main venues table
CREATE TABLE IF NOT EXISTS venues (
  place_id TEXT PRIMARY KEY,
  name TEXT,
  address TEXT,
  street_address TEXT,
  city TEXT,
  state TEXT,
  zip TEXT,
  latitude FLOAT,
  longitude FLOAT,
  rating FLOAT,
  review_count INT,
  phone TEXT,
  website TEXT,
  hours JSONB,
  photos JSONB,
  created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
  updated_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

-- 2. Create the venue_vibes linking table
CREATE TABLE IF NOT EXISTS venue_vibes (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  place_id TEXT REFERENCES venues(place_id) ON DELETE CASCADE,
  vibe_slug TEXT,
  neighborhood TEXT,
  created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
  
  -- Prevent duplicate vibe assignments
  UNIQUE(place_id, vibe_slug)
);

-- 3. Create indexes for better query performance
CREATE INDEX IF NOT EXISTS idx_venues_location ON venues(latitude, longitude);
CREATE INDEX IF NOT EXISTS idx_venues_rating ON venues(rating);
CREATE INDEX IF NOT EXISTS idx_venue_vibes_vibe ON venue_vibes(vibe_slug);
CREATE INDEX IF NOT EXISTS idx_venue_vibes_neighborhood ON venue_vibes(neighborhood);
```

## Querying Your Data

### Example Queries

```sql
-- 1. Get all work-friendly cafes
SELECT v.name, v.address, v.rating
FROM venues v
JOIN venue_vibes vv ON v.place_id = vv.place_id
WHERE vv.vibe_slug = 'work_friendly';

-- 2. Get all venues in SoHo
SELECT v.name, v.address, vv.vibe_slug
FROM venues v
JOIN venue_vibes vv ON v.place_id = vv.place_id
WHERE vv.neighborhood = 'SoHo';

-- 3. Get places that are BOTH work-friendly AND aesthetic
SELECT v.name, v.address
FROM venues v
WHERE v.place_id IN (
  SELECT place_id FROM venue_vibes WHERE vibe_slug = 'work_friendly'
)
AND v.place_id IN (
  SELECT place_id FROM venue_vibes WHERE vibe_slug = 'aesthetic'
);

-- 4. Count venues by vibe
SELECT vibe_slug, COUNT(*) as venue_count
FROM venue_vibes
GROUP BY vibe_slug
ORDER BY venue_count DESC;

-- 5. Find multi-vibe venues (places that match many vibes)
SELECT v.name, COUNT(vv.vibe_slug) as vibe_count
FROM venues v
JOIN venue_vibes vv ON v.place_id = vv.place_id
GROUP BY v.place_id, v.name
HAVING COUNT(vv.vibe_slug) > 3
ORDER BY vibe_count DESC;
```

### Python Queries

```python
from supabase import create_client
from decouple import config
import os

url = config("SUPABASE_URL", default=os.getenv("SUPABASE_URL"))
key = config("SUPABASE_KEY", default=os.getenv("SUPABASE_KEY"))
supabase = create_client(url, key)

# Get all work-friendly cafes in SoHo
response = (
    supabase.table("venues")
    .select("*, venue_vibes(*)")
    .eq("venue_vibes.vibe_slug", "work_friendly")
    .eq("venue_vibes.neighborhood", "SoHo")
    .execute()
)

for venue in response.data:
    print(f"{venue['name']} - {venue['rating']} stars")
```

## Benefits

### 1. No Duplicates
- Each venue stored once, even if it matches 10 vibes
- Updates to venue data (rating, hours) happen in one place

### 2. Rich Querying
- Find places by vibe, neighborhood, or combination
- Discover multi-vibe venues
- Filter by rating, location, etc.

### 3. Scalable
- Indexes make queries fast even with 100,000+ venues

## Troubleshooting

### "Supabase credentials not found"
- Check your `.env` file exists
- Verify SUPABASE_URL and SUPABASE_KEY are set
- Try: `python -c "from supabase_storage import supabase; print(supabase)"`

### "Table doesn't exist"
- Run the SQL from step 3 in Supabase SQL Editor
- Check table names match exactly (case-sensitive)

### "Duplicate key value violates unique constraint"
- This is normal! It means the venue already exists
- The upsert will update the existing record

### No data appearing
- Check return value from `run_grid_search()`
- Verify `save_batch_to_supabase()` returns True
- Check Supabase dashboard for data
